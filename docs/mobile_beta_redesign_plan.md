# 모바일 대응 베타테스트 UI/UX 리디자인 기획안

## 1. 목표 및 컨셉
- **목표**: 백엔드 연동 구조는 유지하면서, 모바일 사용자 중심의 간결하고 직관적인 경험을 제공해요.
- **베타테스트 컨셉**: 제한된 초대 기반 베타 서비스 느낌을 강조해 초기 사용자 커뮤니티를 형성해요.
- **디자인 키워드**: 반응형(Responsive), 모듈형 카드(Card-based), 라이트 다크 듀얼 톤, 마이크로 인터랙션.

## 2. 메인 페이지 리디자인
### 2.1 레이아웃 구조
1. **상단 히어로 영역**
   - 모바일 뷰에서는 풀스크린 높이의 히어로를 사용하지 않고, 60vh로 제한해요.
   - "베타 참여하기" CTA 버튼과 초대 코드 입력 필드를 나란히 배치하고, 모바일에서는 CTA가 우선 보여요.
   - 백엔드 호출 없이도 동작할 수 있는 인라인 폼 검증을 도입해요.
2. **핵심 가치 Proposition 섹션**
   - 3개의 핵심 가치를 카드 형태로 요약해, 모바일에선 스와이프(가로 스크롤) 형태로 노출해요.
   - 각 카드에 간단한 아이콘과 1줄 메시지, "자세히" 마이크로 CTA를 배치해요.
3. **베타 전용 기능 안내**
   - "실험 중인 기능" 섹션을 별도로 두어, 진행 중인 실험 목록을 배지로 표시해요.
   - 모바일에서는 아코디언 UI를 적용해 한 번에 하나의 내용만 확장되도록 해요.
4. **커뮤니티 & 피드백**
   - 실시간 공지 또는 사용자 피드백을 보여주는 마루quee 대신, 모바일에선 탭 기반 피드백 리스트를 제공해요.
   - "피드백 남기기" 버튼을 플로팅 액션 버튼(FAB)으로 배치해 UX를 단순화해요.
5. **푸터 영역**
   - 모바일에서는 간소화해 필수 링크(이용약관, 개인정보처리방침, 고객센터)만 남겨요.

### 2.2 비주얼 및 인터랙션
- 메인 색상은 기존 브랜드 컬러를 유지하되, 모바일에서 대비가 높은 단일 컬러 그라데이션을 활용해요.
- 반응형 타이포그래피 스케일을 적용해 폰트 크기를 장치 너비에 따라 자연스럽게 변경해요.
- FAB, CTA 버튼 등 핵심 인터랙션 요소에 마이크로 애니메이션(0.2s) 적용을 고려해요.

### 2.3 베타 전용 UX 요소
- 상단에 "베타 이용 중" 상태 배너를 고정해 현재 단계와 다음 예정 기능을 안내해요.
- 베타 참여자에게만 열리는 "초대 코드 공유" 카드로 커뮤니티 확장을 유도해요.
- 온보딩 시 3단계(소개 → 기능 둘러보기 → 피드백 안내) 튜토리얼 슬라이드를 제공해요.

## 3. 카테고리별 리디자인 전략
카테고리는 모바일 사용자에게 부담 없는 깊이로 구성하고, 각 카테고리 별 목적에 맞는 UX를 적용해요.

### 3.1 분석/대시보드 카테고리
- **간략 뷰 & 상세 뷰 분리**: 모바일 첫 화면에서는 핵심 KPI 3가지만 카드로 노출하고, "전체 보기" 버튼을 눌러야 상세 데이터 테이블이 나타나게 해요.
- **데이터 시각화**: 모바일에서는 미니 그래프(스파크라인) 중심으로 제공하고, 피벗 테이블은 가로 스크롤 테이블로 축약해요.
- **필터 UX**: 상단에 칩 형태의 필터를 제공해 한 손 조작이 가능하게 해요.

### 3.2 프로젝트/태스크 관리 카테고리
- **상태 기반 리스트**: 칸반 대신 상태별 리스트(예: 진행 중, 예정, 완료)를 아코디언으로 구현해요.
- **퀵 액션**: 각 태스크 카드에 스와이프 제스처를 도입해 상태 변경이나 코멘트 추가를 빠르게 수행할 수 있게 해요.
- **협업 강조**: 베타 사용자 대상의 피드백 기능을 태스크 상세에 통합해, 댓글과 투표 기능을 제공해요.

### 3.3 리소스/자료실 카테고리
- **검색 중심 UX**: 상단에 고정된 검색바와 인기 키워드 칩을 제공해요.
- **다운로드 흐름 간소화**: 모바일에서는 즉시 다운로드 대신 "나중에 받기" 기능을 제공하고, 알림으로 다운로드 링크를 안내해요.
- **콘텐츠 프리뷰**: 문서/영상/이미지는 카드 내 썸네일과 2줄 설명으로 요약해요.

### 3.4 설정/관리자 카테고리
- **중요 기능 우선순위화**: 모바일에서 자주 사용하는 계정, 알림, 접근 제어를 상단에 배치하고, 고급 설정은 접어두어요.
- **에러/상태 안내**: 서버 상태, API 키 정보 등은 카드 기반으로 정리하고, 경고/주의 아이콘으로 시각적 피드백을 줘요.
- **안전 장치**: 민감한 변경은 슬라이드 토글 후 모달 확인 단계를 거치도록 UX를 설계해요.

## 4. 반응형 가이드라인
- **브레이크포인트 제안**: 360px, 480px, 768px, 1024px, 1280px.
- **모바일 퍼스트**: 모바일 CSS를 기본으로 작성하고, 상위 브레이크포인트에서 레이아웃을 확장해요.
- **컴포넌트 재사용성**: 카드, 버튼, 아코디언 등 공용 컴포넌트를 atomic design 기준으로 정리해요.

## 5. 베타테스트 UX 계획
1. **초대 흐름**: 이메일 초대 → 초대 코드 입력 → 온보딩 → 메인 페이지 진입.
2. **피드백 수집**: 앱 내 피드백 버튼, 주간 설문 이메일, 우선순위 투표.
3. **알림 시스템**: 베타 전용 공지, 신규 기능 안내, 사용자 감사 메시지를 푸시 또는 이메일로 제공해요.
4. **유저 리워드**: 활동 포인트와 베타 종료 후 정식 출시 혜택(할인, 기능 개방 등)을 미리 안내해요.

## 6. 구현 및 테스트 플랜
- **디자인 시안**: Figma 등에서 모바일/데스크톱 와이어프레임과 UI 컴포넌트를 정리해요.
- **프론트엔드 구현**: 기존 백엔드 API 연동을 유지하면서, 반응형 레이아웃과 컴포넌트 리팩터링을 진행해요.
- **접근성 테스트**: 모바일 스크린리더, 컬러 대비, 터치 타겟 크기 등을 점검해요.
- **베타 사용자 테스트**: 1차(내부), 2차(초대 사용자)로 나눠 시나리오 기반 테스트를 진행해요.

## 7. 향후 로드맵
- 베타 피드백 수집 → 우선순위 분류 → 개선 배포 주기(2주)를 유지해요.
- 베타 종료 시 정식 출시 페이지로 전환할 수 있도록 컴포넌트 레벨의 토글 구조를 설계해요.
- 데이터 분석을 통해 모바일 전환율, 피드백 응답률 등을 주요 KPI로 모니터링해요.
